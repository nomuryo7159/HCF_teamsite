# Team Site Implementation Plan

> **For agentic workers:** Use subagent-driven-development for implementation and independent spec/code review. Steps use checkbox syntax.

**Goal:** Build and publish the approved public team site with member-only editing.

**Architecture:** React/Vinext app with server-authorized JSON API and D1 shared records. Sites supplies ChatGPT identity, hosting, and database. OWNER_EMAIL remains server-only.

**Tech Stack:** TypeScript, React, Vinext, Cloudflare D1, Drizzle, Zod, Sites.

## Task 1: Data and authorization
- [ ] Create db/schema.ts: records (id, kind, JSON payload, revision, sort order) and editors (email, optional user ID). Generate schema-only migration via npm run db:generate.
- [ ] Create lib/model.ts with shared types, defaults and Zod schemas. All kinds: team, member, rule, phase, task, event, thread, minute, resource. Validate lengths, safe URLs, date order. Team singleton has ID team.
- [ ] Create lib/access.ts pure authorization checks and lib/store.ts server DB access. Owner is designated by OWNER_EMAIL; editor emails live only in editors table. No first-visitor administration.
- [ ] Create app/api/data/route.ts public GET; per-record POST/PATCH/DELETE with server auth, same-origin checks, revision compare and swap. No public email disclosures.
- [ ] Create app/api/editors/route.ts for owner-only list/add/remove. Use parameterized DB access and no untrusted HTML rendering.
- [ ] Create tests/model.test.ts and tests/access.test.ts with invalid dates, unsafe URLs, missing identity, unauthorized identity, owner and permitted editor cases. Run node --experimental-strip-types --test tests/*.test.ts.

## Task 2: Public screen and editing
- [ ] Create app/team-site.tsx and focused components under components/. Public navigation links to all sections; desktop and mobile styles in app/globals.css.
- [ ] Replace app/page.tsx and app/layout.tsx: server optional identity and initial data; no runtime secrets passed to client. Anonymous visitor sees sign-in link; permitted editors see editing controls.
- [ ] Implement form dialogs for all record types, saving states, errors and delete confirmation. Team/member editing, rules, WBS ordering and task grouping, task completion and filters, calendar month navigation, thread links, searchable expandable minutes, resource links.
- [ ] Implement owner-only editor management. Initial content uses only provided names, third member pending, name/mission undecided and empty records.
- [ ] Run TypeScript checking, functional model/access tests, production build. Inspect responsive screen, public access and local-only mock sign-in editing using documented local preview.

## Task 3: Verification and publication
- [ ] Independent spec review followed by code quality/security review; correct findings before deployment.
- [ ] Configure OWNER_EMAIL as secret runtime env through Sites. Declare D1 as DB in hosting manifest. Apply generated migration to local DB.
- [ ] Package using site-workflow.mjs; retain credential only in tool session memory and pass via hidden stdin. Source helper pushes verified source and produces archive.
- [ ] Set audience public as approved, save version, deploy saved version and verify terminal success. Report URL and actual verification limits.
